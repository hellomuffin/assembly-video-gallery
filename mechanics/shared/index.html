Working prototype · schematic physics tests

One executor.
Two furniture assemblies.

The same action code assembles a table and a shelf from separate descriptions, with gravity and contact enabled. Connections become rigid only after the required abstract tightening actions.

These are mechanics tests, not the finished visual product.

Simple boxes stand in for furniture CAD. A virtual gripper replaces anatomical hands; tool turns are abstract actions. The existing visual showcase remains the presentation reference.

Completed tightening · normal speed

A separate loosening test removed the connection and the beam fell approximately 45 cm. This fixture test declares a 3 mm connector clearance bridged by the simplified fastening model.

What passed

  • Both furniture types completed from two randomized, initially non-overlapping layouts each.
  • Misaligned components, wrong tool location or direction, insufficient torque, and nonfinite turn inputs were rejected.
  • Incomplete tightening did not hold the unsupported beam; complete tightening did; loosening removed the connection.
  • Recorded active constraints matched the declared grasps and fastened connections.
  • Sampled geometry penetration stayed below 3 mm. This is a 25 Hz recording audit, not an all-step collision certification.

What is shared—and what is still missing

  • Shared: grasp, move, align, turn and release behavior. Furniture descriptions supply dimensions, mass, connector endpoints, tool sites and tightening thresholds.
  • Explicit reference policy: these demonstrations use known assembly poses and a correct operation order. The executor does not automatically choose the correct part for an assistant.
  • Current limits: proxy geometry; noncolliding assisted gripper; abstract tool torque/turns; no human reach or balance; no tool-access collision check; no overload breakage of fastened joints.
  • Next integration: production CAD and the accepted hand/room presentation, with the same causal connection rules. More connector types and obstacle-aware motion remain to be implemented.

These results demonstrate reuse across two descriptions. They do not establish arbitrary-furniture generalization or a zero sim-to-real gap.
